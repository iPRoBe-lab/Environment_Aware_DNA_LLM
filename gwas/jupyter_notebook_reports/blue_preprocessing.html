01 — Trait-value computation: environment-adjusted BLUEs (fixed-effects model)¶

The problem this solves. Each hybrid is grown in a wildly unbalanced set of environments (median 10 environments/genotype, range 1–127). A simple average of a genotype's plot records therefore confounds its genetics with which environments it happened to be grown in — a genotype tested mostly in high-yielding sites looks good for reasons that aren't genetic. Feeding such averages to GWAS injects that confounding into the association signal.

What this notebook does. For each trait × stress category, fit a model that estimates a genotype effect adjusted for environment, replicate and block, and take the genotype BLUE (Best Linear Unbiased Estimator) as the trait value. The stress categorization is kept byte-identical to the upstream definition; only the per-genotype trait value changes. Output: 16 blue_pheno/{trait}_{stress}.csv tables (Taxa,<trait>), the phenotype input to BLINK.

Model (fixed-effects, base R lm), per trait × stress category

$$\text{trait}_{ij} = \mu + g_i + d_j + \varepsilon$$

  • $g_i$ genotype — fixed → its estimate is the BLUE we want (no shrinkage, correct for stage-2 GWAS)
  • $d_j$ environment:rep:block — fixed → one nested factor that absorbs the environment, replicate and block effects, removing the environment-imbalance confounding
  • $\varepsilon$ residual

Solved with base R lm (compute_blue.R). This is a fixed-effects BLUE: standard, fully deconfounds environment, fast at this scale, and the genotype values — which is all the GWAS consumes — are what we keep. (A mixed model with rep/block as random effects barely changes those values and is impractically slow with ~4,300 genotypes as fixed effects, so it is not used here.)

2. BLUE computation¶

Run compute_blue.R (skips if the 16 outputs already exist; the command is shown for provenance). It fits the model above per trait × stress category and writes blue_pheno/{trait}_{stress}.csv. corr_BLUE_vs_naive is how far the adjusted values move from a naive average — the lower, the more the environment imbalance was distorting that condition; n_aliased counts genotypes not separable from the block design (dropped).

3. QC — how much did the environment adjustment move the trait?¶

If naive averaging were unbiased, BLUE ≈ naive mean (points on the y=x line). Departure from the line is the confounding the BLUE removes; lower correlation = more environment-imbalance distortion.

fig, axes = plt.subplots(4, 4, figsize=(15, 15)); axes = axes.ravel(); k = 0
for trait in TRAITS:
    for cat in STRESS_CATS:
        ax = axes[k]; k += 1
        blue = pd.read_csv(PHENO_OUT/f"{trait}_{cat}.csv")          # Taxa,<trait>
        naive = (ph[ph.CATEGORY==cat].groupby("genotype")[trait].mean())
        naive = (naive - naive.mean()).rename("naive")
        m = blue.merge(naive, left_on="Taxa", right_index=True)
        x, y = m["naive"], m[trait]
        ax.scatter(x, y, s=5, alpha=0.3, rasterized=True)
        lo, hi = np.nanmin([x.min(), y.min()]), np.nanmax([x.max(), y.max()])
        ax.plot([lo, hi], [lo, hi], "r--", lw=0.8)
        ax.set_title(f"{trait} / {cat}\nr={np.corrcoef(y, x)[0,1]:.2f}", fontsize=8)

4. BLINK inputs¶

Genotypes are unchanged, so the GAPIT map is regenerated from GENO.csv (idempotent) and the BLUEs feed the existing Nextflow pipeline. The job manifest gwas_jobs.csv already points at blue_pheno/{trait}_{stress}.csv, so re-running BLINK is just:

cd local_experiments/nextflow && nextflow run main.nf --model BLINK

(BLINK settings unchanged — PCA.total=5, GAPIT defaults — so the only thing that changed between runs is the trait value.)

def create_gapit_map(geno_path, output_path):
    # GAPIT map (CHROM,POS,SNP ID) from GENO.csv column names 'S{chrom}_{pos}'
    cols = pd.read_csv(geno_path, nrows=0).columns[1:]
    df = pd.DataFrame({"CHROM": [int(c.split("_")[0][1:]) for c in cols],
                       "POS":   [int(c.split("_")[1])     for c in cols], "SNP ID": cols})
    df.to_csv(output_path, index=False); print(f"map written: {output_path} ({len(df)} SNPs)"); return output_path
