Coordinate liftover (B73 v4 → v5) & meta-QTL overlap¶

G2F maize hybrid panel — placing published stress meta-QTLs in the study's v5 coordinates¶

Our GWAS is reported on Zm-B73-REFERENCE-NAM-5.0 (v5), but the published maize stress-associated meta-QTLs (MQTLs) we compare against are reported on B73 RefGen_v4. To intersect them, the MQTL intervals must be lifted v4 → v5. This report documents that liftover end-to-end and validates it.

Tools. CrossMap v0.7.0 with the MaizeGDB v4↔v5 chain files (download.maizegdb.org/Zm-B73-REFERENCE-NAM-5.0/chain_files/, built by ATAC/A2Amapper alignment of the two assemblies). A chain named A_to_B.chain maps coordinates from A to B.

1. Meta-QTL table → v4 BED¶

The published table gives, per MQTL, a chromosome (embedded in the MQTL name, e.g. MQTL4.3 → chr 4) and a physical interval in megabases. We convert to BED, keeping coordinate conventions exact:

  • reported physical positions are 1-based inclusive;
  • BED (what CrossMap consumes) is 0-based half-open → bed_start = start − 1, bed_end = end.

2. Lift v4 → v5 with CrossMap¶

CrossMap walks the chain alignment and emits one row per contiguous alignment block. Because the two assemblies differ by countless small insertions/deletions, a multi-megabase interval comes back as many small blocks — this is expected, not an error.

3. Collapse blocks → one v5 interval per meta-QTL¶

For comparison against point SNPs we need a single interval per MQTL. We keep the consensus chromosome (most mapped bp), cluster its blocks (a gap > 1 Mb starts a new syntenic cluster), and take the outer bounds of the dominant cluster. This is equivalent to lifting the two endpoints and snapping each to the nearest mappable base. Each MQTL is flagged:

  • ok — clean 1:1 lift (single cluster, span preserved);
  • ok_dominant — recovered cleanly; a small (<5%) stray block was trimmed;
  • review — the interval genuinely splits across v5 locations (inspect manually).
In [4]:
GAP, RATIO_TOL = 1_000_000, 1.5
per = defaultdict(lambda: defaultdict(list))
for b in blocks.itertuples(index=False):
    per[b.MQTL][b.chr].append((int(b.start), int(b.end)))
v4map = {r.MQTL:(str(r.chr), int(r.start), int(r.end)) for r in bed.itertuples(index=False)}

recs = []
for mqtl in bed.MQTL:
    chrom_bp = {c:sum(e-s for s,e in ivs) for c,ivs in per[mqtl].items()}
    cons = max(chrom_bp, key=chrom_bp.get); total = sum(chrom_bp.values())
    cons_frac = chrom_bp[cons]/total
    ivs = sorted(per[mqtl][cons]); clusters = [[ivs[0]]]
    for s,e in ivs[1:]:
        (clusters.append([(s,e)]) if s-clusters[-1][-1][1] > GAP else clusters[-1].append((s,e)))
    dom = max(clusters, key=lambda cl: sum(e-s for s,e in cl))
    v5s, v5e = min(s for s,_ in dom), max(e for _,e in dom)
    dom_frac = sum(e-s for s,e in dom)/total
    off = sorted(c for c in chrom_bp if c != cons)
    _, v4s, v4e = v4map[mqtl]; v5span, v4span = v5e-v5s, v4e-v4s
    ratio = round(v5span/v4span, 3)
    status = ("ok" if (len(clusters)==1 and ratio<=RATIO_TOL and cons_frac>0.99 and not off)
              else "ok_dominant" if dom_frac>=0.95 else "review")
    recs.append(dict(MQTL=mqtl, v5_chr=cons, v5_start=v5s+1, v5_end=v5e, v5_span_bp=v5span,
                     v4_span_bp=v4span, span_ratio=ratio, n_blocks=sum(len(v) for v in per[mqtl].values()),
                     n_clusters=len(clusters), dominant_frac=round(dom_frac,4),
                     off_chr=",".join(off) if off else ".", status=status))
iv = pd.DataFrame(recs)
print("status:", iv.status.value_counts().to_dict())
iv.to_csv(WORK/"mqtl_v5_intervals.tsv", sep="\t", index=False)

4. Validation¶

(a) Endpoint-lift vs block-collapse. The intuitive method — lift only the two endpoints and use [lifted_start, lifted_end] — is computed here for comparison. Where an endpoint is mappable the two methods should agree exactly; disagreements localise to endpoints that fall in an unalignable gap.

pts = []
for r in bed.itertuples(index=False):
    pts.append((r.chr, r.start, r.start+1, f"{r.MQTL}__s"))   # 1-bp start
    pts.append((r.chr, r.end-1, r.end,     f"{r.MQTL}__e"))   # 1-bp end
pd.DataFrame(pts).to_csv(WORK/"ends_v4.bed", sep="\t", header=False, index=False)
crossmap_bed(CHAIN45, WORK/"ends_v4.bed", WORK/"ends_v5.bed")

lifted = defaultdict(dict)
for l in open(WORK/"ends_v5.bed"):
    p = l.rstrip("\n").split("\t")           # strip newline so the tag parses cleanly
    name, w = p[3].rsplit("__", 1); lifted[name][w] = (p[0], int(p[1])+1)
identical = differ = gap = 0
for mqtl in bed.MQTL:
    d = lifted.get(mqtl, {})
    if "s" not in d or "e" not in d: gap += 1; continue           # an endpoint landed in a gap
    blk = iv.loc[iv.MQTL==mqtl].iloc[0]
    lo, hi = sorted([d["s"][1], d["e"][1]])
    if d["s"][0]==d["e"][0]==blk.v5_chr and abs(lo-blk.v5_start)<2000 and abs(hi-blk.v5_end)<2000:
        identical += 1                                            # both methods agree
    else:
        differ += 1                                               # mappable but disagree = rearrangement
print(f"{len(bed)} meta-QTLs — endpoint-lift vs block-collapse: identical {identical}, "
      f"differ {differ} (rearrangement), endpoint-in-gap {gap} (recovered only by block-collapse).")

Summary¶

  • The published stress meta-QTLs were lifted v4 → v5 with CrossMap v0.7.0 and the MaizeGDB chain, then reassembled into one v5 interval per MQTL by consensus-chromosome dominant-cluster collapse.
  • Span is preserved for the large majority of intervals (span ratio ≈ 1); a small number flagged review/ok_dominant coincide with genuine v4↔v5 rearrangements.
  • Endpoint-lifting and block-collapse agree wherever endpoints are mappable; block-collapse additionally recovers intervals whose endpoint lands in an assembly gap.
  • Caveat. Only ~96.8% of positions map between v4 and v5; the remainder fall in repeat/ structural-variant/gap regions with no unique homolog and cannot be lifted — inherent to comparing two independent assemblies, not a defect of the chain file.

The resulting v5 meta-QTL intervals are what the model-prioritized loci are intersected against.
