03 — LD decay & the candidate-locus window¶

G2F maize hybrid panel — averaged-trait vs BLUE-trait BLINK¶

A significant GWAS SNP is a tag, not usually the causal variant: the causal site sits somewhere in the linkage-disequilibrium (LD) block around it. The block's width — set by how fast r² between SNP pairs decays with distance — is the ± window to scan for candidate genes around each hit. This notebook measures it and applies it, in three steps:

  1. LD decay (full 437K panel) → derive the ±16 kb (half-decay) and ±32 kb (conservative) windows.
  2. Candidate loci per run → apply the window to the averaged- and BLUE-trait BLINK hits.
  3. Positional concordance → how much the two runs' loci overlap, at ±16 and ±32 kb.

1. LD decay on the full 437K panel¶

Why the full panel. LD decay is a property of the population, not of whichever markers we test. The GWAS scans on the curated 98,026-SNP set (MAF/call-rate QC + LD-pruning of the 437,214 PHG calls), but LD-pruning deliberately deletes the high-LD pairs that define decay — so measuring decay on the pruned set would deflate it. We therefore estimate decay on the full 437K panel. The table below confirms the split is sound: the dropped markers are mostly rare/high-missingness (QC) or redundant in-LD tags (pruning), i.e. exactly what you don't want in a scan but do want for decay.

plink computes r² for all SNP pairs within 300 kb, with no r² floor (--ld-window-r2 0) so the low-r² tail — which is the decay — is kept. We use the MAF ≥ 0.05 set, standard for LD-decay (rare variants give noisy, downward-biased r²). Python only averages plink's r² into 1 kb bins.

def bin_decay(ld_file, WIN=300, BIN=1):
    nb = WIN//BIN; s = np.zeros(nb); c = np.zeros(nb, dtype=np.int64)
    for ch in pd.read_csv(ld_file, sep=r"\s+", usecols=["BP_A","BP_B","R2"], chunksize=2_000_000):
        d = (ch.BP_B.to_numpy()-ch.BP_A.to_numpy())/1000.0; r2 = ch.R2.to_numpy()
        ok = (d>0)&(d<WIN); b = (d[ok]//BIN).astype(int); np.add.at(s,b,r2[ok]); np.add.at(c,b,1)
    mid=(np.arange(nb)+0.5)*BIN; mr=np.where(c>0,s/np.maximum(c,1),np.nan)
    return pd.DataFrame({"dist_kb":mid,"mean_r2":mr,"n_pairs":c}).dropna()

from scipy.optimize import curve_fit
N_IND = 4928   # individuals in the LD panel (PLINK .fam)

# Hill & Weir (1988) expected-r² decay (Remington et al. 2001 form), with a free BACKGROUND term c.
# This related/structured hybrid panel's LD plateaus well above 0, so vanilla Hill-Weir (which
# assumes decay to ~0) fits poorly; the background form fits well. Fit one curve per SNP set and
# read the half-decay off the FITTED curve (so it does not depend on the 300 kb distance cap).
def hill_weir(dbp, rho, c):
    C  = rho * dbp
    hw = ((10+C)/((2+C)*(11+C))) * (1 + ((3+C)*(12+12*C+C**2))/(N_IND*(2+C)*(11+C)))
    return c + (1.0-c)*hw

def fit_decay(d):
    x = d.dist_kb.values*1000.0; y = d.mean_r2.values
    (rho, c), _ = curve_fit(hill_weir, x, y, p0=[1e-4, 0.12], bounds=([1e-8,0],[1e-2,0.6]), maxfev=60000)
    yhat = hill_weir(x, rho, c); R2 = 1 - ((y-yhat)**2).sum()/((y-y.mean())**2).sum()
    grid = np.arange(1, 300001); fg = hill_weir(grid, rho, c)
    short = fg[0]; half_lvl = (short + c)/2; half = grid[np.argmax(fg < half_lvl)]/1000.0
    return dict(short_r2=short, background=c, half_kb=half, R2=R2, rho=rho)

Deriving the windows. We fit the Hill & Weir (1988) expected-r² decay model (Remington et al. 2001 form) to the binned r² (MAF ≥ 0.05), adding a free background term because this related hybrid panel's LD plateaus well above zero (~0.16). Vanilla Hill–Weir, which assumes decay to ~0, fits this panel poorly (R² ≈ 0.63); the background form fits well (R² ≈ 0.9). The half-decay distance — where the fitted curve falls halfway from its short-range value to the background — is ~16 kb (matching a simple empirical read of the curve). This gives the primary ±16 kb window, with ±32 kb (2× half-decay) as a conservative bound. Reading half-decay off the fitted curve makes it independent of the 300 kb distance cap.

2. Candidate loci per run — averaged vs BLUE BLINK¶

Two BLINK runs, identical genotypes and settings, differing only in the phenotype: environment-averaged (naive) vs two-stage BLUE (the env-confounding fix). For each, take the Bonferroni-significant SNPs (p < 0.05 / 98026), expand each to ±16 kb, and merge overlapping intervals per chromosome into candidate loci.

def sig_snps(base, cond, thr=BONF):
    g = [x for x in glob.glob(str(Path(base)/f"{cond}_BLINK"/"GAPIT.Association.GWAS_Results.BLINK.*.csv"))
         if "(NYC)" not in x]
    if not g: return pd.DataFrame(columns=["SNP","Chr","Pos"])
    df = pd.read_csv(g[0], usecols=["SNP","Chr","Pos","P.value"])
    for c in ["Chr","Pos","P.value"]: df[c] = pd.to_numeric(df[c], errors="coerce")
    return df[df["P.value"] < thr].dropna(subset=["Pos"])

def merge_intervals(df, w):                         # per-chrom merged [pos-w, pos+w] intervals
    iv = {}
    for chrom, g in df.groupby("Chr"):
        xs = sorted((p-w, p+w) for p in g.Pos); out=[]; cs,ce = xs[0]
        for s,e in xs[1:]:
            if s<=ce: ce=max(ce,e)
            else: out.append((cs,ce)); cs,ce=s,e
        out.append((cs,ce)); iv[int(chrom)] = out
    return iv

3. Positional concordance — averaged vs BLUE (±16 and ±32 kb)¶

Do the two runs nominate the same genomic regions? Two views, both reported below:

  • *_snps — raw significant-SNP counts and exact shared SNP IDs. Window-independent.
  • *_loci_16 / *_loci_32 — significant SNPs expanded by ±window and merged into candidate regions; shared = regions overlapping between runs.

Note on merged loci: widening the window can only merge nearby SNPs into fewer regions, so *_loci_32 ≤ *_loci_16 by construction (it's merging, not a change in signal), while shared can only rise as matching gets more lenient. The genomic bp covered still grows with the window.

def overlap_count(A, B):                            # # of A-intervals overlapping any B-interval
    h = 0
    for ch, ivA in A.items():
        ivB = B.get(ch, [])
        for s,e in ivA:
            if any(not(e<bs or be<s) for bs,be in ivB): h += 1
    return h

rows = []
for c in CONDS:
    so, sn = sig_snps(OLD,c), sig_snps(NEW,c)
    row = {"condition": c,
           "avg_snps": len(so), "blue_snps": len(sn),                 # window-independent
           "shared_snps": len(set(so.SNP) & set(sn.SNP))}             # exact SNP-ID overlap
    for wkb in (WINDOW, WINDOW_C):
        A, B = merge_intervals(so, wkb*1000), merge_intervals(sn, wkb*1000)
        na, nb = sum(map(len,A.values())), sum(map(len,B.values()))
        sh = overlap_count(A, B)
        row[f"avg_loci_{wkb}"]=na; row[f"blue_loci_{wkb}"]=nb; row[f"shared_{wkb}"]=sh
    rows.append(row)

Result. Even at the lenient ±32 kb window, only a small fraction of loci are shared — the averaged and BLUE runs nominate almost disjoint sets of regions. Identical genotypes and settings; the only difference is how the trait value was built. So BLINK's nominated loci are highly sensitive to phenotype construction in this panel: the locus count is stable, the locus positions are not.

Summary¶

  • Window. LD decay on the full 437K panel gives a stable half-decay of ~16 kb → primary candidate window ±16 kb, conservative ±32 kb. Use these for snpEff -ud / candidate-gene scans. (Absolute r²<0.2 is unreliable here — elevated background LD.)
  • Per run. Averaged and BLUE BLINK give comparable candidate-locus counts.
  • Concordance. They overlap on only a small fraction of positions even at ±32 kb — BLINK loci are highly sensitive to phenotype construction, so that choice must be fixed and justified before the loci are treated as findings.
